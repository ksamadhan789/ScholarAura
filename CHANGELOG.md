# CHANGELOG.md — ScholarAura

Short entries for meaningful changes. Newest first. No source code here.

## 2026-09-22

### Added
- A "Student ID card" upload section now shows right above "Submit your entry" on a competition's own page (`app/competitions/[slug]/SubmissionForm.tsx`) — a student who hasn't uploaded their ID card yet can do it right there instead of being sent to their profile page first. Saves to the same profile-level field as before (`POST /api/account/id-card`), reused automatically for every future competition — this is purely a second, more convenient place to add it, not a second copy.

### Changed
- Competition entry submission (`SubmissionForm.tsx`) brings back the "Or paste a link to your work" field alongside file upload — an entry now needs either a file or a link (or both), not file-only. The file-only restriction from earlier today was reconsidered; with the direct-to-Drive upload no longer needing a fallback for size reasons, there's still value in letting a student link to work hosted elsewhere (e.g. a YouTube video entry).
- Competition entry submission now uploads the file directly from the browser to Google Drive instead of through our own server — `lib/google/driveService.ts`'s new `createResumableUploadSession()` starts a Drive resumable-upload session server-side (auth stays server-only) and hands the browser a one-time URL it PUTs the file bytes to directly, which Google's upload endpoint supports via CORS for exactly this. Only that small session-start request and the final confirm (file ID + metadata) go through our own function; the actual bytes never touch Vercel's ~4.5MB request-body cap, so the shared `MAX_UPLOAD_BYTES` (`lib/uploadValidation.ts`) is back to the original 25MB for both the competition-entry-file and student-ID-card uploads. New `POST /api/competitions/[slug]/submit/upload-session` and `POST /api/account/id-card/upload-session` routes; `POST /api/competitions/[slug]/submit` and `POST /api/account/id-card` now confirm an already-uploaded file (JSON body) instead of receiving the raw bytes themselves — still downloads the file back from Drive server-side to check its real size and magic bytes before trusting it, since the browser's own claims about what it uploaded aren't trusted. New shared `lib/directUpload.ts` (`uploadFileDirect()`, client-only, XHR-based for real upload-progress events) — both forms now show a progress bar while uploading.
- Competition entry submission (`SubmissionForm.tsx`) dropped the "Or paste a link to your work" field — file upload is now the only way to submit an entry, since direct-to-Drive upload removed the size ceiling that made the link field a necessary fallback. `submissionUrl` stays on the `CompetitionEntry` model and in the admin entries table/CSV export for any already-submitted links, just no longer collected from students going forward.

### Fixed
- Attaching an oversized file to the competition-entry-file or student-ID-card upload gave the confusing "Attach a file or paste a link to your work" error with no explanation, since an oversized upload never reliably reaches the server's own size check — Vercel drops a request body over its own platform limit first, before our code runs. Both upload flows (`SubmissionForm.tsx`, `EditProfileForm.tsx`'s ID card section) now check the file's size against the shared `MAX_UPLOAD_BYTES` limit the moment it's picked, before attempting any network request, and show a specific "That file is X.XMB — must be under 4MB" message instead. Confirmed via Playwright: selecting an oversized file now fails immediately with zero network calls made.
- Event edit page's certificate-template hint told admins to design their Google Slides template with placeholders `{{STUDENT_NAME}}`/`{{EVENT_NAME}}`/`{{CERTIFICATE_ID}}` — none of which the certificate generator actually replaces (`lib/certificateGeneration.ts` looks for `{{NAME}}`/`{{EVENT_TITLE}}`/`{{CERTIFICATE_NUMBER}}`). Following the old hint would silently produce a certificate with unfilled placeholder text. Fixed to match the real ones, and expanded both the event and competition edit forms' hints to list the full set (`{{NAME}}`, `{{EVENT_TITLE}}`, `{{CERTIFICATE_NUMBER}}`, `{{DATE}}`, `{{CERTIFICATE_TYPE}}`, `{{COLLEGE}}`, `{{SIGNATORY_NAME}}`, `{{SIGNATORY_TITLE}}`) instead of only 3 of the 8 that actually work.
- The new student-ID-card / competition-entry-file uploads (`lib/uploadValidation.ts`) were capped at 25MB, which exceeds Vercel Functions' hard ~4.5MB request-body limit — any real-sized file (e.g. a scanned document) was silently dropped by the platform before the route handler ever saw it, surfacing as "Attach a file or paste a link to your work" even though a file was clearly attached client-side. Lowered the cap to 4MB, the same limit already proven to work in production for the profile-resume upload.

### Added
- Students can now upload a photo/scan of their student ID card once on their profile (`/dashboard/profile`, new "Student ID card" section) instead of pasting a Google Drive link into an external form — reused automatically for every competition, admin-viewable per entry. New `GET/POST/DELETE /api/account/id-card` (self) and `GET /api/admin/users/[userId]/id-card` (admin), storage in `lib/studentIdCardStorage.ts` (mirrors the existing profile-resume Drive layout), new `User.idCardFileId/idCardFileName/idCardContentType` columns.
- Competition entry submission (`app/competitions/[slug]/SubmissionForm.tsx`) now supports directly uploading the entry file (image, PDF, Word or ZIP, up to 25MB) in addition to the existing "paste a link" field — either or both can be filled in, addressing students getting confused pasting a Drive share link for every entry. `POST /api/competitions/[slug]/submit` now accepts `multipart/form-data` with an optional file; new `GET /api/competitions/[slug]/submission-file` (self-view) and `GET /api/admin/competitions/[slug]/entries/[entryId]/file` (admin), storage in `lib/competitionEntryFileStorage.ts`, new `CompetitionEntry.submissionFileId/submissionFileName/submissionFileContentType` columns. The admin entries table (`/dashboard/competitions/[slug]/entries`) and CSV export now show the uploaded file (or link) and a "View" link to the entrant's ID card.
- New shared `lib/uploadValidation.ts`: one allow-list (images, PDF, Word, ZIP) and 25MB size cap for every "upload a file instead of pasting a link" flow, plus a magic-bytes check (the same approach the existing profile-resume PDF check used) so a file's actual content is verified against its declared type, not trusted on the label alone.

### Fixed
- Event/competition registration's "open the Google Form after payment" step almost always hit its own blocked-popup fallback in practice: `window.open(url)` ran after an awaited `fetch` (checkout, then for paid entries another awaited verify-payment call inside the Razorpay success handler), and that gap breaks the direct-click gesture chain browsers require before allowing a popup — so most real entrants saw the "Your browser blocked the Google Form" banner instead of the form actually opening. Fixed in `app/events/[slug]/RegisterButton.tsx` and `app/competitions/[slug]/EntryButton.tsx` by opening a blank tab synchronously inside the click handler (before any `await`, so it's still within the browser's user-activation window) and navigating that tab to the real form URL once the URL is known; the tab is closed on every path that doesn't end up showing a form (errors, cancelled payment, no form configured), so it never lingers as a stray blank tab. Verified against a standalone Playwright repro: the old await-then-`window.open(url)` pattern was reliably blocked, the new open-blank-then-navigate pattern reliably wasn't. The manual "Open the Google Form" link fallback (and its banner) stays in place for the rare case where even the blank tab is blocked.

### Fixed
